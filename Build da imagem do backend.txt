1) No seu computador (local)
Envie o que mudou com sync.sh.

Backend (código Python):
./deploy/sync.sh --backend

Frontend (HTML/CSS/JS):
./deploy/sync.sh --frontend

Scripts de deploy/config:
./deploy/sync.sh --deploy

Tudo de uma vez:
./deploy/sync.sh --all

Se quiser usar IP direto:

REMOTE_HOST=167.234.225.126 ./deploy/sync.sh --backend

2) No servidor (remoto)
Build da imagem nova do backend e deploy blue/green:

Verifique qual é a atual:
docker images phylogentree-backend --format "table {{.Tag}}\t{{.CreatedAt}}"

cd /home/ubuntu/app					### veja a possibilidade de tentar 'docker build --pull=never -t phylogentree-backend:5 .'
docker build -t phylogentree-backend:2 ./backend
./deploy/deploy.sh 2
Isso:

sobe o container novo (blue/green),
faz health‑check,
troca o upstream do Nginx,
remove o container antigo.
3) Frontend
Se você só mudou frontend, basta o sync.sh --frontend.
Não precisa rebuild de container, porque ele copia direto para /opt/phylogentree/frontend/current.

4) Verificação rápida

curl -sS https://phylogentree.org/api/
curl -I https://phylogentree.org
Dicas rápidas

Se mudou variáveis de ambiente, edite backend.env no servidor e rode um novo deploy.sh (para recriar container com env atualizado).
Se mudou Nginx do host, depois de copiar, rode:
sudo nginx -t && sudo systemctl reload nginx
Se quiser, posso te passar um “fluxo de exemplo” completo (backend + frontend + validação) para você rodar uma vez do zero e confirmar que ficou claro.

Tags das imagens (versão)

Use sempre um número crescente: phylogentree-backend (line 1),  (line 2),  (line 3)…
Isso é o “versionamento do build”.
Guarde em um log simples (ex.: CHANGELOG.md com data + tag).
Blue/Green (nomes)

Não mude os nomes dos containers: sempre backend-blue e backend-green.
O script alterna automaticamente entre eles.
Você só escolhe a tag da imagem no deploy.
Fluxo recomendado

Build da nova imagem com tag nova:
docker build -t phylogentree-backend:3 ./backend
Deploy usando o tag:
./deploy/deploy.sh 3
Como saber qual está ativo

docker ps --format '{{.Names}} {{.Image}} {{.Ports}}'
O ativo será o que está exposto no phylogentree_upstream.conf (9001 ou 9002).

---------------------------------

Como usar o deploy.sh nas atualizacoes:

Build a nova imagem:
docker build -t phylogentree-backend:2 ./backend
Rode o deploy:
chmod +x deploy/deploy.sh
./deploy/deploy.sh 2
Ele vai:

subir backend-green em 9002,
fazer health check,
trocar o upstream do Nginx,
recarregar Nginx,
remover o backend-blue.
Se quiser, posso ajustar o deploy.sh para:

aceitar tag completa (ex.: repo:tag),
usar /health se voce quiser adicionar esse endpoint.


Criei o sync.sh com flags (--backend, --frontend, --deploy, --all) e um arquivo de exclusões.

Arquivos:

sync.sh
rsync-exclude.txt
Uso:

chmod +x deploy/sync.sh

./deploy/sync.sh --backend
./deploy/sync.sh --frontend
./deploy/sync.sh --deploy
./deploy/sync.sh --all
Se precisar ajustar o destino:

REMOTE_HOST=1.2.3.4 REMOTE_USER=ubuntu ./deploy/sync.sh --backend
FRONTEND_TARGET=/opt/phylogentree/frontend/current ./deploy/sync.sh --frontend
Se quiser, também posso adicionar uma flag --config para subir apenas .env/configs.

sudo mkdir -p /opt/phylogentree/deploy
sudo tee /opt/phylogentree/deploy/backend.env >/dev/null <<'EOF'
PUBLIC_BASE_URL=https://phylogentree.org
EOF

./deploy/sync.sh --backend --deploy --dry-run
./deploy/sync.sh --backend --deploy

cd /home/ubuntu/app
docker build -t phylogentree-backend:2 ./backend
./deploy/deploy.sh 2
